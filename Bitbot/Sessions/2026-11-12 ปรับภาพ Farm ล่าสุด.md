# 2026-11-12: ปรับภาพ Farm และ Release 1.1.0

## เป้าหมาย

ใช้ภาพ PNG ล่าสุดของปุ่ม Farm ในตัวโปรแกรมที่ build เป็น `.exe`

## สิ่งที่ทำ
- ยืนยันว่า `config.json` อ้าง `farm-1` ไปยัง `even/Farm/farm-1.png`
- ตรวจภาพล่าสุดขนาด 147×111 และ `SHA-256` ขึ้นต้น `149F9FAF`
- rebuild `dist/Rubitdd-Bot.exe` และตรวจ archive ว่ามี `even\\Farm\\farm-1.png`
- แก้ `build.bat` ให้หยุดเมื่อไฟล์ `.exe` ถูกล็อกหรือ PyInstaller ล้มเหลว
- แก้ `make_release.bat` ให้สร้าง SHA-256/`release.json` ด้วย Python และตรวจ exit code ทุกขั้น
- สร้าง `Rubitdd-Bot-Release.zip` ที่บรรจุ `Rubitdd-Bot-update.exe`; manifest เวอร์ชัน `1.1.0` และ SHA-256 ตรงกับ zip

## ไฟล์ที่แก้
- `even/Farm/farm-1.png`: เปลี่ยนภาพ template Farm เป็นภาพล่าสุด
- `dist/Rubitdd-Bot.exe`: build ใหม่พร้อม template ล่าสุด
- `Bitbot/Modes/Even.md`: บันทึก template note
- `build.bat`, `make_release.bat`: ทำให้ build/release fail fast และสร้าง manifest เสถียรขึ้น
- `Bitbot/Changelog.md`, `Bitbot/Project/Build and Release.md`: บันทึก release workflow ล่าสุด

## ผลการตรวจ
- ruff: ไม่ได้รัน เพราะ environment ไม่มี module `ruff`
- pytest: ไม่ได้รัน เพราะ environment ไม่มี module `pytest`
- project_check: ผ่าน 29 template paths, packaging bundle list และ Python compile
- compileall: ผ่าน
- build: PyInstaller สำเร็จ และเปิด `.exe` ได้นานเกิน 5 วินาทีโดยไม่ crash
- package: `release.json.sha256` ตรงกับ `Rubitdd-Bot-Release.zip`
- ทดสอบกับเกมจริง: รอผู้ใช้ทดสอบ

## พบระหว่างทาง
- `Rubitdd-Bot.spec` bundle โฟลเดอร์ `even/` อยู่แล้ว จึงไม่ต้องเพิ่มพาธใหม่
- รอบ build แรกพบ `.exe` เก่ายังเปิดอยู่ ทำให้ PyInstaller เขียนทับไม่ได้ จึงเพิ่มการตรวจ error ใน `build.bat`
- PowerShell ที่ `make_release.bat` เรียกเคยสร้าง hash ไม่สำเร็จแต่สคริปต์ยังรายงานสำเร็จ จึงย้ายการสร้าง manifest ไป Python
